# Executive Summary

Cyberattacks are surging: in 2023 global network attacks rose ~35% year-over-year, with costs expected to exceed $10.5 trillion by 2025. Small-to-medium organizations (SMBs) are frequent targets – nearly 43% of breaches in 2025 hit SMBs, and 80% of ransomware assaults now focus on companies <1,000 employees. However, these groups typically lack affordable, expert-level defenses. Traditional NIDS/IDS generate volumes of raw alerts that only experts can decode, leaving smaller organizations exposed. Concurrently, threat actors have become faster and stealthier: the average attack “breakout” inside a network occurs in just 48 minutes, with 79% of intrusions in 2024 being *malware-free* (relying on credential theft and hands-on-keyboard tactics). Generative AI has further amplified risks: attacker-crafted phishing now achieves a 54% click rate vs. 12% for human-crafted messages.

**KairosAI** addresses this gap. It is an intelligent NIDS/SOC tool aimed at non-experts in SMBs and educational settings. Using open-source networking libraries (Scapy, PyShark), lightweight backend (FastAPI/Python), and ML/anomaly techniques (Random Forest, Isolation Forest), KairosAI will monitor traffic in real time. Critically, it leverages large language models (e.g. Llama 3 via Ollama/OpenAI) to *explain* detected anomalies in plain language. Dashboards (React/Chart.js) present alerts, flows, and incident reports. Unlike commercial IDS suites (CrowdStrike, Cisco SecureX, Splunk, Darktrace, etc.), KairosAI is designed to be low-cost, easy to deploy, and transparent. In our research phase, we surveyed state-of-the-art AI/NIDS literature and industry trends. Our findings confirm the need for explainable, ML-driven detection systems, especially as attackers exploit AI and living-off-the-land techniques. The slides and Q&A below detail our methodology, comparisons, risks, and the path forward for KairosAI, emphasizing its novelty in real-time detection with XAI and suitability for resource-constrained environments.

# Complete System Workflow

1. **Packet Capture (Networking Layer):** Using tools like **Scapy** and **PyShark**, we continuously sniff network interfaces (or parse PCAP files). This raw capture includes packet headers and payloads where possible. Because payloads may be encrypted (e.g. HTTPS), KairosAI focuses on *metadata* (IP/port, sizes, timing).  
2. **Feature Extraction:** Packets are aggregated into flows (e.g. 5-tuple: src/dst IPs, ports, protocol, time window). We compute features such as packet counts, byte counts, flag statistics, inter-arrival times, and entropy of payload segments. These features are key inputs to the detection algorithms. Processing is done in Python, normalizing or encoding categorical data (protocols). Data is stored in **SQLite** for quick access and logging.  
3. **Machine Learning Detection:** The feature vectors feed into ML models. **Random Forest** (supervised) is trained on labeled samples (captured from datasets like CIC-IDS or small lab events) to recognize known attack patterns. **Isolation Forest** (unsupervised) flags anomalies by identifying outliers in the feature space. If a sample’s predicted probability of threat exceeds a threshold, we label it “suspicious”. These thresholds are tuned during testing to balance false positives.  
4. **Explainable AI (LLM Layer):** For each flagged alert, we prepare a summary of key features (e.g. “High port-scanning rate from IP 10.0.0.5”). We then query a local **LLM (Llama 3)** via Ollama or OpenAI’s API with a prompt like: “Explain why this traffic is suspicious and what response is recommended.” The LLM generates a human-readable explanation, leveraging its training on security text. This output is validated against known rules (e.g. contains certain keywords) to avoid hallucination.  
5. **Dashboard & Reporting:** A React-based UI fetches alerts and explanations from the backend. Using **React Flow** we visualize network relationships; **Chart.js** plots traffic trends over time. Users see color-coded alerts (with XAI text) and can drill down. Reports (PDF/HTML) are auto-generated via FastAPI endpoints, summarizing incidents with both data and LLM narrative.  
6. **Data Flow Summary:**  
   - **Input:** Live packets → 
   - **Process:** Capture → Feature Extration → Model Scoring → XAI Explanation → 
   - **Output:** Alert logs + Human-readable explanations in UI and reports.  

Throughout, decision points include: when to sample (every packet vs. batch), how often to call the LLM (to limit API costs, e.g. only for high-priority alerts), and how to retrain models (scheduled or online learning).

# Workflow Description

**Step-by-Step Process:** In everyday terms, KairosAI operates as follows:

1. **Capture:** The backend listens to network traffic (via Scapy/PyShark) like a digital guard. Every packet (with headers) is noted. This is similar to how tools like Wireshark or Zeek work, but our system does this internally.

2. **Feature Extraction:** Packets are grouped (e.g. by source IP) into “flows”. For each flow, KairosAI calculates numbers like: how many bytes have been sent, which protocols are used (HTTP, DNS, etc.), time between packets, and so on. These become a “fingerprint” of that flow.

3. **Detection:** These fingerprints go into our trained ML models. Random Forest evaluates them (e.g. does this pattern look like a known port-scan or data exfiltration?). Isolation Forest checks if a flow is an outlier compared to normal traffic. If either model marks it suspicious, an alert is raised.

4. **Explainable Layer:** When an alert fires, our system packages the key features (“Source X sent Y MB over an unusual port”). It then asks the LLM to interpret: “Security analysts, why is this suspicious and what should we do?” The LLM responds in clear prose (“The IP 10.0.0.5 contacted many ports rapidly, indicating a possible port scan. It may be a precursor to intrusion, so consider blocking it and checking that host.”). This text is appended to the alert.

5. **Dashboard & Reporting:** Alerts (with LLM text) are pushed to the React UI. Here, users see a list of suspicious events, each with a “Threat Level” and explanation. They can also view charts of traffic volume and a network graph. One click generates a concise incident report summarizing what happened, enriched by the LLM’s insights.

6. **Decisions:** At each stage, decisions include: setting detection thresholds (tuned during testing), choosing how many features to compute (limited by processing time), and when to invoke the LLM (we may skip minor alerts to conserve API calls). Each decision is documented for refinement.

In summary, data flows from raw packets into structured features, through automated analysis, and out as user-friendly alerts. This end-to-end pipeline (capture→analysis→explanation) is our core contribution, turning complex network data into actionable intelligence for any user.
