The Local Network Security Challenge

Vulnerabilities in Educational and Small Organization Networks

Core Pain Points for Campus & Local Networks

1

Alert Overload Without Context

Legacy IDS solutions spit out thousands of raw, cryptic network log entries daily that are difficult for IT staff to filter and parse.

2

Difficulty Interpreting Network Activity

Analyzing raw TCP/IP packet captures or hex streams requires deep forensic training, making it hard to quickly pinpoint root causes.

3

Limited Cybersecurity Expertise

Small school and organization IT departments generally have limited security staff, making continuous manual threat monitoring unfeasible.

4

Slow Identification of Suspicious Behavior

Without real-time behavioral telemetry, scanning or spoofing attacks can go undetected for weeks, risking data integrity.

Campus Network Threat Frequency (Probes)

Campus subnets encounter high rates of automated scans and MAC/IP manipulation attempts due to diverse and shared network endpoints.
Campus Network Context: Campus networks contain student systems, labs, administrative systems and shared devices, making fast identification of abnormal activity important.

Round 1 Feedback → Round 2 Focus

Narrowing Threat Scope for Reliable and Verifiable Detection

Round 1 Scope

Broad Network Threat Detection

1

Ambitious Multi-Vector Coverage

Attempted to capture all classes of malware, intrusions, and anomalous exploits simultaneously.

2

Unfocused Feature Engineering

Broad features led to higher false positives and limited model specificity on individual attack patterns.

3

Complex Live Verification

Difficult to simulate and prove end-to-end detection rates across generic network traffic streams.

Round 2 Refinement

Focused Detection of 3 Attacks

1

Port Scanning

Detect reconnaissance scan patterns across multiple ports using specialized network features.

2

SYN Flood DDoS

Capture volumetric TCP SYN connection rates and analyze incomplete handshake behaviors.

3

ARP Spoofing

Inspect conflicts and changes in local IP-MAC address mappings in real time.

Rationale for Narrowed Scope: Narrowing the scope allows attack-specific feature engineering, stronger testing, clearer validation, and a reliable live demonstration.

Detection & Explanation Methodology

A Rigorous Pipeline Separating Algorithmic Detection from LLM Explanation

1

1. Packet Capture

Scapy/PyShark continuously monitors local interfaces.

2

2. Feature Extract

Extracts IPs, Ports, Protocols, Rates, Flags, IP-MAC mappings.

3

3. ML & Rules

Determines threat classification (e.g. Random Forest + IP-MAC check).

4

4. LLM Explain

Llama 3/Ollama translates classified events into plain English.

5

5. Dashboard UI

Renders live telemetry, alert status, and explanations.

Algorithmic Detection (ML & Rules)

Responsibilities: Determining if an attack is happening based on traffic variables.

  • Port Scan: Flags connection counts to consecutive destination ports (Random Forest).
  • SYN Flood: Checks half-open connections and TCP SYN packets/second thresholds.
  • ARP Spoofing: Stateful rule checks verifying active IP-MAC mapping mismatches.

AI Explanation Layer (Llama 3)

Responsibilities: Translating logs and features into understandable text and recommended actions.

  • No Decision-Making: The LLM does *not* detect the threat; it only explains it.
  • Plain English Translation: Converts hex logs, IP strings, and ports to human context.
  • Actionable Intelligence: Suggests responses (e.g. "Isolate host 192.168.1.105").

Limitations & Scalability

A Realistic Appraisal of Prototype Boundaries and the Roadmap for Future Expansion

Current Scope & Limitations

  • Attack Domain Limits: Currently limited to detecting Port Scanning, SYN Flood, and ARP Spoofing.
  • Environment Scope: Verified in controlled, local virtual subnet environments rather than enterprise scale.
  • Response Scope: Focused on detection, real-time alerting, and LLM explanation. Automated blocking or containment is currently out of scope.
  • ML Model Dependencies: Anomaly detection thresholds depend heavily on clean local network baseline training datasets.
  • Encrypted Payloads: Operates strictly on TCP/IP packet header metadata and flow statistics; deep payload inspections are limited by encryption.

Future Scaling Roadmap

  • Attack Class Expansion: Integrate support for additional classes such as DNS tunneling, credentials brute forcing, and internal spoofing.
  • Distributed Sensor Architecture: Deploy lightweight physical sensor nodes across multiple campus subnets feeding a central collector.
  • SIEM & Operations Integration: Forward telemetry into standardized platforms (e.g. syslog, Splunk, Elastic) for unified alerting.
  • Threat Intelligence Feeds: Pull live reputation updates and malicious IP lists to block known bad actors.
  • Automated Incident Response: Implement programmatic host isolation and automated firewall rules based on approved playbooks.
